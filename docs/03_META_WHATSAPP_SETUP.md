# Meta WhatsApp Setup — Official Route Only

## Required Meta assets
- Meta Business Portfolio
- WhatsApp Business Account (WABA)
- Meta Developer App with WhatsApp product
- Business phone number
- Phone Number ID
- WABA ID
- App ID
- App Secret
- System-user/permanent access token for production
- Webhook verify token generated by us

## Required permissions
Use only permissions required by the official WhatsApp Business Platform, principally:
- `whatsapp_business_messaging`
- `whatsapp_business_management`

Exact permissions/scopes and Graph API version must be verified against current Meta documentation during implementation.

## Authentication rule
Never ask the coding agent to store the user's Facebook password. If Meta requires login, 2FA, business verification, number verification, or owner consent, stop and ask the owner to complete that step interactively.

## Webhook URLs
Example:
- `GET https://wa.example.com/webhooks/meta/whatsapp` — verification challenge
- `POST https://wa.example.com/webhooks/meta/whatsapp` — events

The endpoint must be publicly reachable via HTTPS with a valid certificate.

## Subscriptions
Subscribe the app/WABA to the message events needed for incoming messages and delivery/read status updates.

## Number registration
Use Meta's official phone registration flow for Cloud API. Do not rely on QR sessions or WhatsApp Web.

## Existing-number coexistence
If the chosen account/region supports WhatsApp Business App coexistence, test it. Do not assume eligibility. If coexistence is unavailable, follow Meta's official migration/registration process.

## Implementation rule
Pin a supported Graph API version in configuration. Do not hard-code examples from old documentation such as `v18.0`.
